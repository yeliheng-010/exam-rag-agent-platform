# 智能教学干预与自适应练习 Agent 设计

## 目标

把已经完成的学生错题诊断和班级诊断转化为可执行练习建议，形成“诊断证据 -> 推荐正式题组 -> 教师确认发布/学生开始练习 -> 新作答回流诊断”的闭环。

推荐系统只能选择数据库中已审核的结构化题组，不生成题目，不自动发布班级任务，不绕过现有空间和班级权限。

这里的“已审核结构化题组”指题组草稿审批后生成在正式 `question_groups` 表中的 `active` 记录；`review_status=private` 表示正式题组的可见范围，不等同于待审核草稿，不能据此把私有正式题组排除出练习和推荐。

## 架构方案

采用共享领域服务 `ExamInterventionService`：

1. 班级推荐使用 `ExamAnalyticsService` 获取高频错题和班级权限。
2. 学生推荐使用 `ExamPracticeService` 获取当前学生未掌握错题。
3. 候选集使用 `ExamPracticeService.ListQuestionGroups`，因此只包含当前用户可读空间内的正式题组。
4. 班级已发布题组通过 `ExamAssignmentRepository` 排除；教师可显式要求包含已发布题组用于复习。
5. Agent 工具和 HTTP API 调用同一领域服务，避免两套推荐口径。
6. 班级页面展示推荐结果，教师点击“用于发布”后进入现有发布表单，最终写入仍由 `ExamAssignmentService` 完成。

## 推荐信号

### 班级信号

- 高频错题的题号、题干、错误率、受影响学生数和来源题组。
- 来源题组的考试域、学科和题组类型。
- 已发布题组集合。

### 学生信号

- 当前学生尚未标记为 `mastered` 的错题。
- 错题来源题组的考试域、学科和题组类型。
- 学生对候选题组最近一次练习状态。

## 确定性排序

每个候选题组按以下信号累加分数：

- 与错题来源为同一题组：100 分，理由 `targeted_review`。
- 学科一致：40 分，理由 `same_subject`。
- 题组类型一致：25 分，理由 `same_group_type`。
- 考试域一致：15 分，理由 `same_domain`。
- 学生已做过且正确率低于 60%：20 分，理由 `low_accuracy_retry`。

候选没有任何诊断信号时保留为低优先级补充练习，理由 `supplemental_practice`。排序依次使用分数、题组更新时间、题组 ID，保证结果稳定可复现。

不使用题干关键词拼接或模型自由打分，因为当前题组还没有统一知识点标签，字符串相似度容易把表面相似误判为同一知识点。后续知识点体系建立后再替换为知识点向量/图谱匹配。

## 输出

`ExamPracticeRecommendationResult` 包含：

- scope：`class` 或 `student`
- class：班级模式下的目标班级
- diagnosis：使用的错题证据摘要
- recommendations：正式题组、题库名、题数、分数、理由、是否已发布、最近练习
- warnings：没有错题信号、没有候选题组等确定性提示

Agent 工具 `exam_practice_recommendation` 使用紧凑 XML 风格上下文，并要求模型只解释已有推荐，不编造题组 ID。

## 权限与副作用

- 班级模式必须通过 `ExamAnalyticsService.GetClassAnalytics`，仅 active teacher/assistant 可用。
- 学生模式只能读取当前 session owner 自己的错题和可读题组。
- HTTP 班级推荐接口使用 viewer 路由，但业务服务仍执行班级写角色检查。
- 推荐服务完全只读。
- 教师必须在前端发布表单再次确认标题、说明和截止时间。

## 前端流程

班级分析页增加“推荐练习”命令：

1. 请求班级推荐 API。
2. 在独立对话框展示诊断依据和推荐题组。
3. 点击某条推荐的“用于发布”。
4. 关闭推荐框，打开现有发布练习表单并预填题组和标题。
5. 教师确认后调用原有 `createClassAssignment`。

不新增嵌套卡片；推荐列表使用表格/平铺列表，并提供空数据、加载和错误状态。

## 验收标准

1. 班级推荐只允许教师/助教，学生请求返回 403。
2. 学生推荐只使用自己的未掌握错题。
3. 推荐项都来自当前用户可读的正式题组，并能通过原发布接口导入班级空间。
4. 默认排除已发布题组；显式允许时可推荐原题组复习。
5. 相同输入产生稳定排序和理由。
6. Agent 工具、HTTP API 和班级页面共享同一推荐结果。
7. 没有错题或候选时返回明确空结果，不让模型臆测。
