# 评测副本题组动态关联设计

## 目标

当 RAG A/B 评测对知识文件副本重新切块后，检索结果中的 Chunk ID 与正式题库保存的 `question_chunk_refs` 不再一致。评测需要在不修改正式题库、不重切正式知识库的前提下，恢复检索结果对应的结构化题组，使结构化解析率和答案覆盖率成为有效指标。

## 边界

- 正式 Chunk ID 关联仍是第一优先级，行为保持不变。
- 动态关联只由 `EvalResolver` 启用，普通讲解、练习和显式题组查询不启用。
- 全流程只读，不写 `question_chunk_refs`、`question_groups`、`questions` 或正式知识库。
- 联合评测允许一个运行包含多个来源题库；不能只使用运行记录的 `question_bank_id` 限定候选。
- 关联失败或候选不唯一时返回 `none`，不得猜测。

## 数据流

1. 使用现有 HybridSearch 检索评测副本，保留 Chunk ID、Chunk 正文和 SearchTrace。
2. 使用正式 `question_chunk_refs` 和 `question_groups.source_chunk_ids` 尝试精确关联。
3. 精确关联失败时，从请求中的评测知识库读取知识文件 `file_hash`。
4. 通过相同 `file_hash` 找到正式来源文件，并用 `required_retrieval_phrases` 定位命中的来源文件。
5. 加载这些来源文件已关联题库中的题组详情。这里使用文件级回退，因为历史英语题组存在 `question_chunk_refs` 和 `source_chunk_ids` 都为空的真实数据；只沿 Chunk 引用会漏掉整篇题组。
6. 只有检索正文实际包含至少一个检索金标短语时，才启用来源候选判定，避免用金标掩盖检索失败。
7. 在来源文件的小候选集内，只使用 query、题组标题、题号和题干判定；不再让相邻题占主导的检索正文参与题组评分。
8. 完全等价的重复导入题组按规范化题干、选项和答案签名折叠；内容不同的并列候选仍保持歧义拒绝。
9. 仅当最佳候选达到最低证据阈值，且相对第二名有明确优势时接受关联。
10. 使用关联题组构造现有结构化上下文，并在结果中记录来源和置信度。

## 锚点规则

- 归一化保留 Unicode 字母和数字，统一为小写，忽略空白、Markdown 标记和标点差异。
- 来源候选的 query 锚点长度为 2 个 rune；题号明确命中额外计 12 分。
- 来源候选最佳分至少为 3；若存在第二候选，最佳候选至少领先 2 分且达到第二名的 1.25 倍。
- 未提供检索金标时保留通用 fallback：检索正文锚点长度为 6、query 锚点长度为 4、query 权重为 3，最佳分至少为 4，领先至少 3 分且达到第二名的 1.25 倍。
- 置信度综合最佳命中强度和与第二名的分离度，范围为 `[0,1]`。
- 不满足阈值时保持 `none`，置信度为 0。

## 结果契约

`context_source` 增加：

- `structured_question_group`：正式 Chunk ID 或来源 Chunk ID 精确关联。
- `evaluation_anchor_match`：评测副本经文件哈希收敛后由稳定文本锚点动态关联。
- `none`：未关联或候选不唯一。

每条案例增加 `association_confidence`。结构化解析率同时统计前两种来源；UI 显示中文来源标签和动态关联置信度。

## 答案证据金标

25 条 A/B 案例的 `required_phrases` 从正式题组的正确答案或解析文本中选取：

- 选择题优先使用结构化上下文中的 `Answer: <选项>`。
- 有稳定文本答案的填空题使用答案公式或解析结论。
- 仅有图片答案的题目先使用当前结构化上下文中可稳定识别的答案证据；不得把临时副本 Chunk ID 当作答案金标。

金标文件仍由评测请求显式提交，不写数据库。

## 错误处理与安全性

- 缺少 file hash、检索正文未命中检索金标、找不到正式来源题库或没有唯一候选时返回未关联，不将其视为运行错误。
- repository 查询错误会终止当前案例并写入现有 `error` 字段。
- 所有数据库查询都带 `tenant_id`，知识库 ID 先经过现有权限校验。
- 不新增 schema、migration 或持久化表。

## 验收标准

- 精确关联测试保持通过。
- 动态关联能够匹配唯一候选，歧义候选和弱证据保持未关联。
- 评测结果能区分三种来源，并持久化 `association_confidence`。
- 25 条案例都有非空答案证据金标。
- 联合 A/B 运行的结构化解析率目标不低于 0.95，答案覆盖指标不再因空金标失真。
- 两次相同配置运行的关联结果稳定。
- 验证前后正式 `question_chunk_refs` 行数和内容摘要不变。

## 已知数据边界

- E01 的检索金标未进入 Top20，因此保持 `none`，这是检索召回缺口。
- M25-05、M25-06、M25-08 已关联正确题组，但正式答案/解析只保存图片 URI，结构化上下文没有稳定文本答案；这些案例的答案覆盖仍失败，需要后续答案图片 OCR 或人工结构化，不应通过修改关联规则掩盖。
- HybridSearch 对同分 Chunk 的返回顺序可能变化；核心结果签名稳定，但完整 `retrieved_chunk_ids` 顺序不作为确定性验收条件。
